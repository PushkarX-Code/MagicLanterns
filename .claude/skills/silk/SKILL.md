# Silk

Silk is the one motion vocabulary for everything Pushkar builds: **things lift, glow and settle.** The source of truth is `silk/` in this repo:

- `silk/MOTION.md`: principles, tokens, moves, changelog. Read it before writing any motion.
- `silk/silk.js`: tokens and moves (GSAP).
- `silk/silk.css`: CSS twin, generated by `node silk/build.mjs`.
- `silk/demo.html`: the live reference.

## When building motion

1. Use Silk's moves and tokens. Pick an intent (`settle`, `lift`, `glide`, `flight`…), never a raw ease or a one-off duration.
2. In a new project, copy `silk/silk.js` and `silk/silk.css` in, or import them, and call `silk.use(gsap, plugins)`.
3. Follow the principles: arrive slow, leave fast; focus pulls instead of fades for important things; overshoot only on small touched things; transform, opacity and filter only; reduced motion always respected.
4. If something new is needed, build it in Silk's style and show Pushkar a frame-by-frame demo before it ships.

## When Pushkar approves new motion

Update Silk in the same change. Add the token or move to `silk/silk.js`, run `node silk/build.mjs`, add it to `silk/demo.html`, bump `VERSION`, and log it in the changelog in `silk/MOTION.md`. Unapproved experiments never go into Silk.
